# AICAflow player framework

[Documentation](../../docs/README.md)

`music_player.c` provides the enDjinn playlist UI, progress bar, seeking,
AFV display and playback lifecycle. Supply `songs.h` and `PLAYER_*` macros,
then include it from `code/main.c`.

## Loading

- `PLAYER_SHARED_BANK_FILE`: keep one bank resident across songs.
- `PLAYER_SONG_BANK_FILE`: load a separate bank for each song.
- Per-song AFB and AFV reads are stepped through the enDjinn loop.
- AFX and AFC reads are synchronous.

The playlist supplies filenames, byte sizes and optional DSP/tempo/gain
metadata. The player installs the DSP scene and applies instance tempo.
Generate assets separately with the authoring tools.

## Display and controls

`PLAYER_LIST_BYTES` and `PLAYER_LIST_HEADING` select the size shown in the
playlist. The info line reports AICA flow-image, sample and setup costs.
With a shared bank, per-song sample bytes are zero; the shared bank is still
resident. `SAV` estimates setup reuse as `(NOTE count - setup count) * 36`
bytes, not a measured file-size difference.

The optional [AFV visualisation](https://github.com/dfchil/AICAforge/blob/main/docs/specs/authoring-formats.md#afv--visualisation-sidecar)
is generated by AICAforge. The enDjinn loop
handles rendering, input and the START+A+B+X+Y exit chord.

See the [classical player](../music_player/README.md) for an integration and
[Runtime asset formats](../../driver/format/docs/assets.md) for driver file layouts.
